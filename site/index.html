Lay the keel first.

Keellay is a vendor-agnostic, spec-driven development framework for projects built with AI coding agents. It keeps one method — roles, process, artifact formats, gates and checks — and lays it into your project.

The idea

The keel goes down first. The hull is built on it.

Keellay keeps one method versioned in one place. A project does not copy it: keellay init lays the method in — a small configuration, the project's documents and indexes, role skills generated for that project, and checks wired into git hooks and CI.

Coding agents do the work by reading those files; the owner decides at the gates; the checks hold whatever agent wrote the change.

Who does what

CLI

Deterministic work: the same input always gives the same output. Lays out files, renders role skeletons, resolves paths, merges spec deltas, runs checks.

Agent

Judgment, following one of Keellay's written procedures. Analyses a project, fills a role's project sections, writes a plan, implements, reviews.

Owner

Decisions. Approves a change and its path, accepts a plan, says yes before anything is written into an existing project.

greenfield

An empty project

Gets the default layout, the constitution, the core roles and the checks for its level. No configuration up front.

brownfield

An existing project

Is analysed first: structure, agent instructions, skills, documents, hooks and CI. Keellay proposes keep, convert or archive for each artifact. Nothing is written before the owner's yes.

Right-sized ceremony

The project level sets which mechanisms are installed. The path of each change sets what that change goes through — the architect proposes it, the owner confirms.

light

Constitution, core roles, PRD and ideas, plans with done-when, fresh-context review at close, ADRs, lessons, owner gates. Where existing projects usually start.

standard

default

Adds living specs and deltas for behaviour changes; the review also reads the merged specs; a retro before each change closes; CI runs the same checks as the hooks.

strict

A delta for every behaviour change, enforced in CI; spec freshness gate; fresh-context review for every change including fixes; skill evals in CI.

Principles

01

Method, not templates

Versioned in one place; each project gets a small adapter and its own generated roles, checked against a contract.

02

Vendor-agnostic

Plain Markdown and scripts at the core; role skills in the open Agent Skills format; checks in git hooks and CI.

03

The owner decides

Agents restate the request, show options with a recommendation, and act after a yes.

04

Mechanisms over memory

A lesson that repeats becomes a hook, a checklist item or a rule.

05

Right-sized ceremony

A small fix needs no plan; a large change gets specs, a plan and an independent review.
